# Asset and data provenance

Every asset or dataset that ships with Bharat Harvest must have a recorded origin and licence
(TECH.md §5, §10, §13 — "asset provenance is recorded" is part of the definition of done). This
repository is public; never commit assets we do not have the right to redistribute.

## Current state

Most visual content is **procedural and authored in code** in this repository (terrain, parcels,
water and props generated by `apps/client` and `packages/domain`), covered by the project's own
licence. Optional CC0 3D models, CC0 UI sprites and an OFL font (see Register) are used where
available, with primitive fallbacks for models. Region, crop, weather and market values are **original game
data calibrated for gameplay** (inspired by, but not copied from, real Karnataka agriculture) and
are labelled as simulation, not agronomic advice.

Third-party **code** dependencies are tracked by `pnpm-lock.yaml`; their licences are those of the
respective npm packages (three.js MIT, React MIT, Fastify MIT, …).

## Policy for adding assets

1. Prefer procedural content, our own Blender work, or CC0 / CC-BY / commercially licensed assets
   whose terms allow redistribution in a commercial game and in a public repository.
2. **Not allowed:** ripped game assets, assets from inspiration titles (Farming Simulator, Cities:
   Skylines, Anno, …), "free for personal use" assets, or anything without a clear licence.
3. AI-assisted assets: record the tool, version, prompt summary and the tool's commercial-use terms;
   review for resemblance to existing copyrighted work; keep the editable source.
4. Keep originals in `assets/source/`, optimised exports in `assets/processed/`, and add a row below
   **in the same commit** that adds the file. CC-BY attributions also go into the in-game credits.
5. External datasets (soil, rainfall, prices) go in `data/reference/` with source, licence, version,
   retrieval date, units, transformations and checksum (TECH.md §5).
